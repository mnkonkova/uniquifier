# Уникализатор

Берёт папку готовых рилсов (например, партию «бот работ» `h1_t1_c1.mp4` …) и
делает из каждого свою версию, чтобы Instagram не счёл два ролика одним и тем
же. Потом сам проверяет результат тем же видео-хэшем, которым пользуется Meta.

## Как запустить

```bash
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
noise/fetch_sources.sh                      # один раз: скачать 16 шумов
.venv/bin/python uniquify.py pack           # один раз: нарезать их в 76 слоёв

.venv/bin/python uniquify.py run ПАПКА --name bot_уник --dry-run   # посмотреть план
.venv/bin/python uniquify.py run ПАПКА --name bot_уник             # собрать + проверить
.venv/bin/python uniquify.py run ПАПКА --name bot_уник --against output/уже_выложенные
```

Готовое — в `output/<name>/v1/` (каждый новый прогон — `v2`, `v3`…, `latest`
указывает на последний). Рядом лежат `plan.json` (что досталось каждому ролику)
и `dedup_report.json` (все пары с процентом совпавших кадров).

Отдельно проверить любую папку: `.venv/bin/python qa_dedup.py ПАПКА [--against ДРУГАЯ]`.

## Что делается с каждым роликом

| Рычаг | Что | Насколько помогает (замер на «бот работ») |
|---|---|---|
| **Рамка** | приближение 5–14% + сдвиг окна | главный рычаг: сдвиг на 22–40 px → 0% совпавших кадров |
| **Скорость** | ±1–3%, голос не меняет высоту | 26–33% совпавших кадров — сама по себе не спасает |
| **Шум** | один из 76 слоёв (ТВ-помехи, VHS, зерно плёнки, пыль) | ничего: 100% совпавших кадров даже при шуме 25% — это косметика |
| **Метаданные, GOP** | стираются / у каждого свой | на хэш не влияют |

Рамки (33 штуки) подобраны перебором так, что у любой пары нет ни одного
общего кадра и ни одна не режет титры (поля титров — в `config.yaml → framing`).

Кому какая рамка: уникализатор сначала сравнивает **исходники** между собой и
строит граф «кто на кого похож» — по кадрам, а не по именам (у «бот работ»
ролики делят ещё и мемы с кадром продукта, которых в имени нет). Похожие
ролики получают разные рамки. Если рамок не хватает, общую рамку получают самые
слабо похожие пары, и уникализатор пишет, какие.

## Гейт и пороги

Видео-хэш Meta **vPDQ** (открыт в ThreatExchange): кадр раз в секунду → 256-битный
PDQ-хэш → два ролика сравниваются по доле кадров, нашедших «двойника».

* кадры совпадают при расстоянии ≤ **31** бита из 256 (порог PDQ от Meta;
  у случайных кадров в среднем 128);
* почти однотонные кадры (качество PDQ < **50**) не сравниваются — как в vPDQ;
* Meta в примере называет ролики копией при ≥ **80%** совпавших кадров;
* **наш порог — 0%**: пара не проходит, если совпал хоть один кадр. Как
  Instagram взвешивает частичные совпадения, не публикуется, поэтому цель — ноль.

Официальный пакет `vpdq` на macOS не собирается, поэтому сравнение повторено в
`qa_dedup.py` поверх `pdqhash` (тот же эталонный PDQ).

Источники: [vPDQ README](https://github.com/facebook/ThreatExchange/blob/main/vpdq/README.md),
[PDQ & TMK+PDQF — разбор](https://arxiv.org/abs/1912.07745).
